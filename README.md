# DZMM 角色卡导出器

把 [dzmm.ai](https://www.dzmm.ai/) 上的角色导出成 **SillyTavern（酒馆）可直接导入的 v2 角色卡 PNG**。带图形界面：内嵌站点浏览器 + 悬停一键导出。

> 非官方第三方工具，与 DZMM 及其运营方无任何关联。

**2. 内容为成人向（NSFW / R18）**
目标站点是成人平台，导出的卡片会包含成人内容。请确认你已满 18 岁，并在合法合规的环境下使用。

**3. 不要高频请求站点**

**4. 不要把 `webview_data/` 目录发给任何人**
那是内嵌浏览器的会话目录，**里面存着你的 DZMM 登录态**。同理 `config.json` 里有你的保存路径和上次用的开场白。仓库的 `.gitignore` 已经排除它们，请勿手动 add。

**5. 站点接口随时会变**
本工具依赖 DZMM 的内部接口（非公开 API）。站方一改版，抓开场白、长回复这类功能就可能失效 —— 这是正常的。欢迎提 issue，但没法保证一直可用。

**6. 抓开场白需要登录**
站点公开接口的 `firstMes` 字段永远是空的。真正固定的开场白藏在「对话分享」里：短分享（≤5 条消息）不用登录就能整段读到；长分享需要点「查看更早消息」展开，**这一步必须登录**。想在软件里走通这条路径，请在窗口里登录一次 DZMM（登录态只存在本地 `webview_data/`，不会外传）。

**7. 别把导出的卡或截图提交进仓库**
`.gitignore` 已排除 `exported/` 和 `*.png`，请勿手动 add。

## 它做什么

| 功能 | 说明 |
| --- | --- |
| 内嵌站点 | 用 WebView2 内核直接打开 dzmm.ai，搜索 / 切页签 / 翻页 / 登录 全部照常可用 |
| 点图导出 | 悬停角色图浮出「导出角色卡」按钮；或 `Alt`/`Ctrl` + 点击；或开启「直接点图片即导出」后左键单击 |
| 生成真卡 | 组装成 `chara_card_v2`，base64 写进 PNG 的 `tEXt "chara"` 块，酒馆可直接拖入 |
| 自动抓开场白 | 从该卡的「对话分享」里把真正的开场白挖出来写进卡 |
| 长回复要求 | 把「不少于 800 字 + 描写要求」写进卡的后历史指令，导入后回复明显变长 |
| 命令行批量 | 同一个核心也能当 CLI 用：单张 / 整榜 / 整作者 |

## 快速开始

### 环境要求

- Windows 10 / 11（用 WebView2，Edge 自带，无需额外安装）
- Python 3.10+ —— 安装时记得勾选 **Add python.exe to PATH**

依赖只有 **一个**：`pywebview`。`Pillow` 是可选的（只有当站点封面不再是 PNG、需要转格式时才要装），正常用不到。

### Windows 一键启动

```
git clone <你的仓库地址>
cd dzmm-card-exporter
启动导出器.cmd
```

或者直接**双击 `启动导出器.cmd`**。首次运行会自动 `pip install`，装完直接打开窗口，不用手动配任何东西。

### 手动启动

```
python -m pip install -r requirements.txt
python app.py
```

### macOS / Linux

```
chmod +x run.sh
./run.sh
```

`app.py` 会按系统自动挑窗口内核：Windows → WebView2，macOS → 系统 WebKit，Linux → GTK / Qt（Linux 需自行 `python -m pip install 'pywebview[gtk]'`）。

> ⚠️ **只有 Windows 是作者实测过的**。macOS / Linux 那条路径是按 pywebview 文档写的，没有验证过 —— 跑不通欢迎提 issue 或 PR。

### 自检（第一次跑不起来时用）

```
python app.py --selftest
```

会启动窗口、检查脚本注入是否成功、自动导出首页第一张卡，然后打印结果并关窗。

## 怎么用

窗口右下角有一个可折叠的悬浮面板：

| 控件 | 作用 |
| --- | --- |
| 保存到 / 更改 | 导出目录，默认 `%USERPROFILE%\Downloads\DZMM角色卡` |
| 直接点图片即导出 | 开启后左键单击角色图即导出；关掉则点图回到详情页 |
| 覆盖已存在 | 关闭时同名文件跳过，避免重复下载几 MB 的图 |
| 自动抓开场白 | 导出前自动去对话分享里挖开场白 |
| 抓当前页开场白 | 手动抓一次当前角色页的开场白，抓到会填进下面的输入框 |
| 写长回复要求 | 把长回复指令写进卡的 `post_history_instructions` |
| 复制要求文本 | 复制长回复文本，可粘到酒馆的全局后历史指令里 |
| 开场白输入框 | 手动覆盖；填了就优先用它，清空则回到自动抓 |
| 导出当前页角色 | 在 `/character/xxxx` 详情页上导出当前角色 |
| 打开目录 / 导出 JSON | 打开保存目录 / 只导出卡数据 JSON |

### 三种导出触发方式

1. 鼠标悬停在角色图上 → 图片右上角浮出蓝色「导出角色卡」按钮 → 点它
2. `Alt` 或 `Ctrl` + 点击图片 → 直接导出
3. 勾上「直接点图片即导出」后，普通左键点图就导出

## 命令行用法

同一个核心也能脱离界面批量跑：

```
# 单张 / 多张（URL 或纯数字 id 都行）
python dzmm_export.py 3674281 https://www.dzmm.ai/character/3689641 --out D:\cards

# 整个榜单
python dzmm_export.py --tab highest_rated_7d --out D:\cards

# 某个作者的全部卡
python dzmm_export.py --creator <作者主页URL或userId> --out D:\cards

# id 列表文件（每行一个）
python dzmm_export.py --list ids.txt --out D:\cards

# 自动抓开场白（免登录，只对短分享有效）
python dzmm_export.py --tab newest --auto-opening --out D:\cards

# 顺带写入长回复要求
python dzmm_export.py 3674281 --long-reply --out D:\cards
```

榜单可选值：`newest` `games` `highest_rated_1d` `highest_rated_7d` `highest_rated_30d` `highest_rated_all` `competition` 等。

## 工作原理

### 为什么网页上的图不能直接拖进酒馆

1. 页面上的图是 CDN 转出来的 **WebP**（`?format=webp`），右键另存得到 `.webp`，酒馆不认。
2. 把 URL 换成原始对象直链 `/storage/v1/object/public/` 拿到的是真 PNG，**但里面没有任何 `tEXt` 文本块** —— 实测 44 张卡图，`chara` / `ccv3` 块数量为 **0**。
3. 它们是**封面图**，不是角色卡。所以直接拖进酒馆必然报「无效的角色卡文件」。

本工具的做法：从 `/character/{id}` 的页面负载里取 `characterData`（角色名 / 角色介绍 / 标签 / 作者 / 封面），按 `chara_card_v2` 组装 JSON，写进 PNG 的 `tEXt "chara"` 块。

### 开场白是怎么挖到的

1. 每张卡都有「对话分享」，分享页 `/share/{shareCode}` 是**服务端渲染**的。
2. 页面默认只渲染最后 5 条消息，上面写着「还有 N 条更早的消息」。
   - **没有**这行 → 整段对话都渲染出来了 → 第 1 条角色消息**就是开场白**（免登录）。
   - **有**这行 → 需要点「查看更早消息」展开，**这一步要求登录**。
3. 所以工具分两步：Python 先扫一遍免登录的；剩下的交给前端同源 `<iframe>` 加载分享页、点掉展开按钮、再取第 1 条角色消息。
4. **安全阀**：只要「还有 N 条更早的消息」还在，就绝不把第 1 条当成开场白 —— 否则会取到对话中段的内容。

### 为什么导入酒馆后回复变短

**角色卡只带人设，不带输出规则。** 站上的长回复来自它的「预设」（`dzmm.ai/presets` 的预设市场），你只导入角色卡，等于只有人设，所以回复会变短。

本工具默认把一段「长回复要求」写进卡的 `post_history_instructions` —— 提示词里位置最靠后、权重最高的一段，导入即生效。已经导入过的老卡，可以用面板的「复制要求文本」粘到酒馆的全局后历史指令里。

另外还要顺手检查这几处，否则加了提示词也可能没用：

| 检查项 | 在哪 | 怎么设 |
| --- | --- | --- |
| **回复长度上限** | 生成设置 → Response (tokens) | 只有 150~300 会被**硬截断**，调到 **800~1500** |
| **停止字符串** | Stop Strings | 多出一条像 `###` 的就会把长回复从中间切断，清空试试 |
| **上下文长度** | Context Size | 太高会把角色设定挤出去，太低记不住剧情，**6k~16k** 较稳 |
| **模型** | 连接设置 | 小模型天然话少，换 Claude 系 / DeepSeek / Gemini |
| **temperature** | 生成设置 | 太低会一句话说完就停，**0.6~1.0** 比较能展开 |

面板上的「复制要求文本」可以直接取到写进卡里的那段要求，方便粘到酒馆的全局后历史指令。

## 常见问题

**Q：导出的卡里没有开场白？**
A：站点公开接口的 `firstMes` 永远是空的。开场白要从「对话分享」里挖，长分享需要登录。请在软件窗口里登录一次 DZMM，再重新导出。如果这张卡连短分享都没有，那就是抓不到。

**Q：提示 `418` 或者弹出拖动验证？**
A：触发反爬了。停一会儿，用你自己的浏览器打开 dzmm.ai 把验证拖完（IP 会临时放行）。之后请放慢节奏，不要批量刷。

**Q：抓开场白一直失败？**
A：先确认是否已在窗口里登录；另外不是每张卡都有可用的对话分享。

**Q：卡导入酒馆后回复很短？**
A：见上面「为什么导入酒馆后回复变短」，重点查 `Response (tokens)` 上限是不是只有一两百。

**Q：导出的卡能直接在酒馆用吗？**
A：可以。导出的就是标准 `chara_card_v2` PNG，拖进酒馆即可。

**Q：支持 macOS / Linux 吗？**
A：代码跨平台，也给了 `run.sh`，但作者只在 Windows 实测过。

## 已知限制

- 开场白依赖「对话分享」，没有可用分享的卡抓不到
- 站点接口非公开，改版即失效
- 内嵌浏览器与系统浏览器**不共享登录态**（数据在本地 `webview_data/`）
- 打码/敏感的卡也能正常导出（走原始对象直链，不需要 `ciat` 令牌）
- 不做去水印、不做内容审核、不做批量并发

## 目录结构

```
app.py            图形界面主程序（pywebview + WebView2）
inject.js         注入到站点的脚本（找角色 id / 悬停按钮 / 点击拦截 / 悬浮面板）
dzmm_export.py    取数 + 组装 v2 卡 + 写 PNG 的核心，也能当 CLI 用
启动导出器.cmd     Windows 一键启动（首次自动装依赖）
run.sh            macOS / Linux 启动
```

运行期会生成 `config.json`、`webview_data/`、`exported/`，均已 gitignore。
